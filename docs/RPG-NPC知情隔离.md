# NPC 知情隔离

NPC 的言行由独立模型请求生成。GM 仍保留玩家完整经历、任务与状态，用于裁决和环境描写；这些上下文不传入角色请求。

## 回合流程

1. 引擎与可选判定照常处理行动。
2. GM 生成环境与玩家行动结果草稿，不负责 NPC 回应。草稿先缓冲，不直接发送给前端。
3. 感知分发器读取本轮输入、环境草稿及带见证者的旧事实，选择可展示的环境片段，并为可听见、可看见的信息分配角色。所有选文必须逐字来自相应来源，听众必须属于本轮允许的名单。
4. 各 NPC 按顺序独立回应，只收到自己的初始设定、经来源校验的记忆和本轮感知。后回应者能听到前一个人已经公开说出的话；不能读取他的私人记忆。
5. 程序直接组合环境片段与角色言行，没有拿着完整秘密再次改写角色的模型调用。内部推理等额外输出字段不展示、不传播。
6. 最终正文照常结算。知情记录保存在该条消息的 `settlement.npc_knowledge` 中，与结算事实分开；结算不能将额外听众加入这份记录。

私聊只调用对应角色，也只向他记录本轮感知。独自行动仍允许现场角色看到动作，但输入不会自动被当作说出口的话。玩家表达的说法按 `speech` 保存，不保证为真；可观察的现象按 `observation` 保存。

## 来源与旧存档

知情记录包含来源消息、原文、听众以及玩家输入和最终正文的内容摘要校验值。改稿、删除来源或回滚后，不再读取失效的知情记录。记录依附原有消息和存档机制，不需要新增数据库字段或迁移。

旧的玩家摘要、NPC 摘要、原始整段对话、NPC 动态备注、关系里程碑、世界书和全局大事记不进入角色请求。旧存档仅从原文未改变、已结算且明确标有该角色为见证者的事实中挑选候选，再经感知分发器剔除心理和幕后说明；不使用旧事实的自由概括。没有知情证据的旧事可能需要玩家重新告知。

角色的姓名、简介、人设、外貌、背景故事和能力特长作为作者定义的初始自身知识；不直接传入角色卡的关系网络、台词样例或其他角色卡。作者应将角色不知情的秘密放在 GM 世界设定中，避免写进该角色自身知识字段。

长期记录目前以固定 token 预算取最近可容纳的条目，保留原文与来源，不用未经隔离的摘要补齐。已公开但没有传播范围或接收者证据的旧传闻不会自动广播给所有角色。

## 代价与边界

一轮增加一次感知分发调用，并为每个参与角色增加一次独立生成调用。使用模组的快速模型处理分发，叙事模型处理环境和角色。生成相关调用的消耗合并计入本轮叙事 token。

首段文字要等整个场景生成完成后才显示。中途失败或停止时，尚未检查的 GM 草稿不会显示或保存为剧情；失败不会回退到旧的全知叙事路径。已经交付给前端的正文仍走现有中断保存机制。

角色行动仅生成自身尝试，不直接宣告涉及他人的行动成功；既有引擎和结算继续负责结果与数值。新出场者需要进入本轮在场名单后才能参与角色回应。

来源引用、听众集合和请求内容由程序限制；自然语言中的「是否说出口、是否被看见」仍由感知分发模型识别，可能误判。这不是对模型语义判断的绝对保证，也不能完全消除无依据的猜测。

## 验证

`backend/tests/test_rpg_knowledge.py` 检查实际发送给角色的请求：私密任务、心理、旧摘要和旁人记忆不应出现；同时覆盖群聊顺序、私聊边界、改稿失效、旧事实迁移、说法与事实区分，以及失败和取消时不发送草稿。

`backend/tests/test_rpg_knowledge_turn.py` 覆盖真实回合编排、消息落库、结算后记忆读取及存档回滚。
