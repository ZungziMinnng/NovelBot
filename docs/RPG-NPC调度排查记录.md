# RPG NPC 调度排查记录（2026-09-23）

这是 `RPG-NPC调度改动.md` 的续篇。那一篇讲的三件事（删外场简报、推时段时不再因为同屋就跳过她、漏了竖线也能挪）不再重复，需要时只做一句引用。

## 一条铁律：谁准动是引擎的事，去哪儿是模型的事

原先「去哪儿」是 `random.choice` 在候选里抽一个。它没有任何是非判断——厕所、女子浴室、公园在它眼里等价，真实存档里出现过「她被挪到菜市场厕所」。改成模型挑之后，它手上有人设，挑得出说得通的地方。

反过来，「谁准动」永远不能交给模型。跟着玩家的人、许过约的人、站在玩家跟前的人、时段不对的人，这几种判错的代价是她当着玩家的面凭空消失，或者当场毁诺。模型再懂人设也担不起这个。

下次改这块的人最容易犯的错，就是把这条边界挪一挪：让模型顺手一起决定「这个人该不该动」。别动它。

## 调度器能看到多少上下文（实测数字）

一次「结束时段」= 一次 LLM 调用，一次写完所有闲着的 AI 调度角色（不是一人一次，一屋子人玩家会为 N 次往返付钱）。相关常量都在 `backend/app/agents/rpg_turn.py`：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `ACTIVITY_MAX_TOKENS` | 500 | **输出**上限，不是输入 |
| `ACTIVITY_RECENT_CHARS` | 300 | 给它看的「最近一段剧情」= 最后一条 assistant 消息的**尾巴** 300 字 |
| `ACTIVITY_CHARS` | 40 | 存进近况那句话的长度上限 |
| `ACTIVITY_LOG_LINES` | 12 | 近况流水保留行数 |
| `AUX_CALL_TIMEOUT` | 60 | 必须有，见下 |

那个 60 秒不是随手写的：底层 httpx 客户端没设超时，于是 OpenAI SDK 退回它自己的默认值（read 600 秒 × 最多 3 次尝试），单次调用能合法占住半小时。而它跑在 `exclusive_session` 的租约里、心跳会一直替它续期，卡住的不是这一下而是整局——玩家再点什么都是 409。

提示词模板在 `backend/app/prompts/templates/rpg_activity.jinja2`：固定规则部分 1011 字，本次改动前整份约 1911 字。

**调度器看不到的东西**（改之前先对一遍这张单子）：

- 大事记 chronicle
- npc_history
- 场面概要
- 玩家数值、物品栏
- 关系数值、flags、任务
- **其它 NPC 的近况**

它只知道这八样：今天第几天第几格、玩家在哪、这个人在哪、这个人的人设、这个人的近况、上次给这个人记的那句、这个人可去的地方、上一格把这个人挪到了哪。

## 2026-09-23 这次的两处改动

### 1. 人设不再夹 60 字

改动点是 `rpg_turn.py` 里 `idle_npc_activities` 组 prompt 那个字典的 `"persona"` 字段。

查了真实库（`backend/data/novelbot.db`，只读打开）：人设最长 331 字（日向雏田），赫敏 273，澹台红绡 195，范建明 192，陆骁 192，韩曼宁 186。夹到 60 字只剩开头那半句身份介绍，性格、习惯、忌讳全在后面被切光；而模板里明写着「写出来必须像他的性格」，它手上根本没有性格。

代价只是那份名单变长。500 token 的上限管的是输出。

### 2. 加了「玩家上一格发了什么」

新查一条最后的 user 消息，模板里单独一块「玩家上一格说要做的事」。

为什么必须是玩家那句：按「结束时段」**不产生新消息**，所以连按几格时那份「最近一段剧情」一直是同一段，调度每次拿到的输入几乎一样——它当然每次写出差不多的东西。玩家那句是唯一还带着新信息的。

取的是**开头** 300 字（玩家输入重点在前面，「我去公司待一天」），正文相反取**尾巴**（尾巴才是刚发生的）。没有玩家消息时整块不出现，不是一个空标题。

坑一：`rpg_messages` 表**没有 day/slot 列**（只有 location / present），没法按格子精确查，拿的是「最后一条 user」。两条推格子的路上它都正好落在刚结束那一格里，够用。

坑二（下次一定会踩）：模板加了新变量，**必须同步** `backend/app/services/rpg_prompts.py` 里那份变量白名单，否则模板校验直接报「未知变量 said」，`test_rpg_prompts.py` 两条测试当场红。

刻意没动 `npc_activity_log`：它的注释写着「只给人看，不进 prompt」，而且它是每个角色自己的流水；玩家那一侧的事 `rpg_messages` 里现成就有，不用新存一份。

## 解析层修的 4 个缺陷（「点了结束时段但角色不动」的真正原因）

先说结论：**引擎那半边是健康的**。用第 12 局真实配置离线跑过，每个符合条件的时段都把她挪走了。问题全在「把模型写的那行字解析回 id 和地名」这一步。

模型该写「名字：地点｜做了什么」，实际会写成下面这几种：

1. **名字带装饰**：`**韩曼宁**：…`、`【韩曼宁】：…`（Markdown 强调、剧本体）。原先只削引号，于是名字段成了 `*韩曼宁**`，认不出人，整行丢掉——她既没换地方也没有近况，界面上一句解释都没有。现在星号方括号一并削。
2. **两头写反**：`在柜台前排队｜药店`。颠倒过来**两头都废**：地名那侧对不上白名单于是不挪，活动那侧存进去的是一个光秃秃的地名（真实探针里近况就写着「药店」两个字）。判据是「哪一侧整个等于一个候选地名」——活动是一句话，不会恰好等于某个地名。
3. **地名写短**：模组里叫「情趣内衣店」，它写「内衣店」。只认全等的话整行作废。敢放宽是因为**候选池就是这个角色自己那份白名单**（几个地名），不是全量地点表；短名只对上一个才算，对上两个就当没写。注意 `match_place` 那边**不肯**放这个方向（「藏经阁」→「藏经阁顶层」是凭空编造），因为那边的池子是整张地点表。
4. **一句话走两个地方**：「在商场中心逛了逛小店，又转到情趣内衣店门口看了几眼才回家」。这一行**整行丢掉，不是只丢位置**——留着近况的话侧栏写「在家」、近况写她逛商场，玩家看到的是两处对不上（真实存档第 12 局韩曼宁，这就是用户报的那个 bug）。丢了这一格沿用上一句，陈旧但不自相矛盾。

两条**刻意保留的拒绝**：地名不在白名单里的不认（凭空地名会让侧栏显示玩家走不过去的地方）；一句话里两个候选地名的不猜。

## 玩家指令挪不动 NPC：派遣解析的 4 个缺口

都在 `backend/app/agents/rpg_turn.py` 的派遣解析那组正则（`_SEND` / `_SEND_BA` / `_SEND_SUBJ` 及配套）。离线跑了 20 种说法找出来的：

1. **光身的「到 / 来」**：「让她到卧室等我」「喊她来公司」是最自然的支使说法，而共享的那张动词表里只有「回到 / 来到」这类双字词，于是这两句一个字都不动、整句交给 AI，位置改动最后被结算那道「缺少赶来的原文依据」打回——玩家下了指令，三道关一道都没执行。
   **硬约束**：光身的字只敢加在派遣**专用**那张表（`_MOVE_OR_BACK`）里，**绝不能加进 `_MOVE_VERBS`**——那张表还管玩家自己的去向，加了「我到家了」会被读成一次移动。放心的另一半是去处那头由「必须是登记过的地名」兜着：「让她把东西放到桌上」的「桌上」不是登记地名，不认。
2. **句尾的语气词**（`_SEND_TAIL`）：「让她回家去」「叫她来公司吧」结尾那个「去 / 来 / 吧 / 了」原先不在收尾表里，整句对不上。
3. **名字前的副词**（`_SEND_ADVERB`）：「让韩曼宁**先**回家吧」，「先」被一起吃进人名里，全等匹配对不上，整句作废。现在在 `_send_who` 里先削掉一层副词（就 / 先 / 快 / 赶紧 / 马上 / 立刻 / 现在 / 这就 / 自己 / 亲自），而不是往那条本来就长的正则里再加可选前后缀。
4. **宾语提前**（`_SEND_BA`）：「把韩曼宁叫到卧室来」。原先要求使役动词紧挨着人名，提前之后对不上。新加的这条**只收招呼类的动词**（叫 / 喊 / 请 / 派 / 支）——「把她带到卧室」的「带」是携带（玩家自己也过去），归另一条线，收进来会把一次携带记成一次派遣，她被挪走而玩家留在原地。

两个**刻意留着不修**的漏网：「跟韩曼宁说让她回家」（嵌套引语）、「让韩曼宁过来」（没有具名去处）。退回交给 AI 是对的失败姿态。

## 结算取证：那道「缺少该角色赶来的原文依据」

这道闸在 `backend/app/services/rpg_settlement.py` 的 `apply_proposal`，两个方向：同场的人不能没有离场事件就被挪走；在别处的人不能没有赶来的依据就出现在玩家跟前。

这次修的是**证据不该只看 quote 那一句**。真实存档第 12 局：玩家在家等了一晚，正文写「韩曼宁侧身挤进来，带进来一股商场中央空调的气味」——她确实到了，可模型给这条移动配的 quote 是「防盗门那边终于响了。」，一个动作词都没有，于是一条写对了的证据被打回，她留在内衣店；玩家看着她在自己客厅里说话，而侧栏写她在商场。

现在退一步：正文里只要有一句**既提到她、又带到场动作词**（来 / 进 / 回 / 到 / 赶 / 返 / 现身 / 出现 / 推门 / 敲门）就算有依据。

**但是**：带「你」字的句子不算。「你回到柴房，园丁甲正从里屋走出来」里的「回」是玩家自己走的这一趟，她的名字只是同句出现；不排掉的话这句话能把任何人放进屋，那正是这道闸最初要拦的瞬移。这一条是被一个**既有测试**逼出来的（`test_an_npc_elsewhere_cannot_appear_at_the_player_without_coming_over`），当时我的改动让它变红了——**没有改测试，改的是代码**。

已知天花板（代码里有 `ponytail:` 注释标着）：按句子里有没有「你」来分主语，两头都不准——「你抬头，她推门进来」这种真到场会被漏掉（漏了只是位置没跟着改，玩家还能用修改器挪），而「你看见她从里屋出来」这类假到场仍旧拦得住。要更准就得判动作词挂在谁身上，那是一次句法分析，判错的代价是放行凭空瞬移。

## 「跟模组走之后按结束时段又变回四格」不是后端 bug

后端查过两头：推时段那条路不会动这一局自己的时段表（离线模拟过）；数据库里那一行根本没被写过（没有更新时间戳）。

真正的机制在前端 `frontend/src/pages/Rpg/TweakPanel.tsx`：「跟模组走」那颗按钮只是把输入框填上，修改器里所有字段都是**待应用**状态，而任何一次会话数据变化都会触发重置、把没应用的编辑擦掉。只改了提示文案，说清「按了跟模组走还要再按下面的应用才算改完」。

## 下次动这块要知道的几件事

- 仓库是公开的，历史和分支带过真 key 和用户数据；push 前先扫路径。
- 工作区常年挂着几十个未提交改动，未跟踪的新文件覆盖即永久丢失，Write 前先看 `git status`。
