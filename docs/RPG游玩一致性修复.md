# RPG 游玩一致性修复

本次修复覆盖游戏侧审查发现的十二项实现问题，以及时间重复计费、资源不足仍获得收益两项规则问题。

## 回合与恢复

- 同一局从请求接收到叙事、结算和收尾完成，只有一个操作能够写入状态。其他标签页的发言、移动、读档等操作会被明确拒绝。
- 互斥状态存入数据库，短事务提交，不跨模型调用持有 SQLite 写锁。租约持续续期；服务异常退出后，租约最多在两分钟后失效，可以重新操作。
- 停止生成后，半段正文保存和已经开始的结算仍持有本局的操作权，完成后才释放。
- 开始下一轮、移动和推进时间统一检查最新一条 GM 剧情：尚未结算、正在结算、失败或正文修改后尚未重算时，需要先补算。旧回合的失败或部分结算记录不再阻止继续游玩；旧剧情被修改后尚未重算的情况仍需回滚，以免后续剧情建立在已经改掉的内容上。
- “部分变化未采纳”表示核对已经结束：通过核对的变化已保存，其余变化没有写入，可以继续游玩，也可以先重试结算。推进时间或进入下一轮后，要重算旧剧情仍需回滚。仅完全通过核对时，场景收尾才自动扣行动预算，给部分结算保留重试机会。
- 网络或模型流异常也保存已经返回的正文。没有正文时明确报错，不创建无法补算的空回复。
- 新的玩家消息保存动作、物品数量、技能、目标、对话模式、私聊对象和判定属性。刷新后重发也使用原来的操作参数。

## 编辑与存档

- 修改器增加“人物位置”：可选择未出场 NPC，查看本局实际位置，移到模组中的指定地点或玩家身边，也可恢复作息 / 常驻地点。应用即保存且不消耗时间、不生成剧情；移到别处或恢复日常安排会解除跟随，同时清除旧随机位置标记。此操作不修改角色卡或关闭随机移动，后续仍遵循原有活动规则。
- 第一轮玩家输入之前可以编辑开场白，不会把开场白送入没有基线的结算流程。
- 有后续剧情的消息必须通过回滚重发修改；直接编辑会在写入之前被拒绝，避免留下无法恢复的过期结算。
- 最新剧情只有具备结算基线、时间未推进时才能直接编辑。
- 编辑消息前，记录已有存档需要恢复的旧正文和结算信息。恢复存档时，状态与这些消息修订一起恢复。
- 自动存档只有在消息位置和游戏状态都相同时才合并。每轮玩家消息引用对应的回合前存档，重发不会额外撤销之前的地图移动。

## 规则一致性

- 句首明确移动后可继续写逗号、句号或分号分隔的动作与对话，例如“走进藏经阁偏殿，关上门，向里面的人打招呼”。后文不再干扰句首目的地识别；同一输入中继续指定另一个移动目的地时仍不擅自选择。
- 重结算时，其他 NPC 的后续位置变化不再阻止当前场景中无关 NPC 或地点近况的更新。同一角色、同一地点字段的后续改动继续受保护；来源不明的后续变化不再一律称为“人工修改”。
- 剧情必须在引擎确定的地点落脚，不能把已单独登记的偏殿、后院等当作同一场景随意切换。在场角色被结算移到别处时，需要该角色自己的离场事件；不能拿主角的移动或房间描写作为依据。角色确实独自离开、返回日常地点或从外面进来时仍能正常更新位置。
- 自由输入支持“回工位上班”“回工位工作”“去会议室开会”等地点后接工作活动的移动指令。每轮读取模组当前地点表，游玩中新增的地点可直接用于后续移动；否定、问句和未登记子地点仍不会触发移动。
- 召见、派遣、时间变化等引擎操作完成后，重新计算本轮在场名单，并同步到玩家和 GM 消息。
- 不要求选人的动作，用完整角色名单判断关系条件；要求选人的动作，用所选对象判断。
- 远程动作只要有一个合格候选人，就能打开选人窗口；每个候选人再单独校验。
- 非消耗品必须实际持有；技能必须学会且可主动施展。批量物品数量或资源不足时，整笔操作拒绝，不偷偷减少使用数量。
- 模组动作、技能和道具的负数属性效果作为必须足额支付的成本；正数收益不会在成本不足时发放。允许负数的属性按其配置的下限判断。AI 自由叙事造成的属性变化仍按原有结算规则处理。
- 明确消耗一个时段的动作只推进一次时段，不再占用下一时段的行动预算。
- 技能按钮与建议按下一回合开始时的冷却状态判断，不再让玩家多等一轮。
- 发送新消息保留现有聊天记录；旧请求迟到的回调不会污染后续回合。

## 模拟器行动反馈

- 动作、道具和技能传给剧情模型的数值，使用应用上下限后的实际增减；封顶、未定义或未启用的效果不会再被报告为成功获得。
- 本轮行动造成的时间推进同时给出开始与结束时刻，剧情描写这段行动及结果。手动跳过时段仍从新时刻继续；手动跳时后再执行耗时动作时，两段时间分别说明。
- 模拟器主页与聊天页的动作按钮显示时间成本，并在本次即将换时段或跨天时预告结束时刻。主页玩家数值效果预览考虑当前值和上下限；尚未选择对象的关系效果标注为基础效果。
- 引擎结果通过 `engine_result` 立即反馈，同一份明细以 `engine_facts` 保存在回合结算记录中。行动消耗、跨天恢复与最终净变化分别显示，刷新后仍可查看。
- 已由引擎处理的数值和关系效果记录在结算基线中。即使消耗与跨天恢复恰好抵消、或数值已达上限，AI 结算也不能重复应用同项效果。
- 已有存档不需要迁移；新增的起止说明和引擎明细从后续回合开始产生。

## 验证入口与边界

- 后端：`python -m unittest discover -s tests -p 'test_rpg*.py' -q`
- 前端：`npm run test:rpg`、`npm run build`
- 新增后端回归用例使用隔离数据库，模拟模型返回、断线、停止、多个请求和服务中断，不调用真实模型。
- 旧消息没有保存过的操作参数无法准确还原；完整参数重放适用于升级后产生的消息。
- 升级前已经丢失的正文、已经发生的错误结算不会凭空恢复。升级后的编辑会为已有存档保留修订前的消息。
